# コンテンツの定期更新

AI 関連の情報はすぐ古くなるため、月に 1 回程度この手順で見直す。
メインのセッションは **進行役** に徹し、ページの調査と書き換えは章ごとにサブエージェント `chapter-refresher` に任せる。
各章の調査結果はサブエージェントの中で閉じるので、メインのコンテキストには章ごとの短い報告だけが残る。

## ルール

- 対象は、フロントマターの `lastUpdated` が **今日から 2 か月以上前**（`lastUpdated <= 今日 − 2 か月`）のページ
- 1 つの章を 1 つのサブエージェントで処理する。複数の章を 1 つのサブエージェントにまとめない
- 章は **1 章ずつ順番に** 処理する（並列にしない）。前の章の結果を確認してから次の章へ進む
- 1 回の依頼で、対象ページのある全章が終わるまで進める

## 手順

### 1. 準備

1. `main` を最新にし、作業ブランチ `content-refresh/YYYY-MM`（今日の年月）を作る
2. 今日の日付と、しきい値（今日 − 2 か月）を決める
3. 対象ページを洗い出す:

   ```bash
   cd src/content/docs && grep -H "^lastUpdated:" -r . | sed 's/:lastUpdated: */ /' | sort -k2
   ```

   しきい値以前の日付のページを、章ごとにまとめる。

4. 対象の一覧（章ごとのページ数）をユーザーに短く伝えて、そのまま進める。対象が 0 件なら、その旨を伝えて終了する

### 2. 章ごとの更新（順番に繰り返す）

章の順番はサイドバーと同じにする:
`llm-basics` → `rag` → `mcp` → `agents` → `data-sources` → `data-modeling` → `cost-roi` → `anti-patterns` → `use-cases`

対象ページのある章ごとに、次を行う。

1. Agent ツールで `chapter-refresher` を起動する。プロンプトには次を書く:
   - 章のディレクトリ（例: `src/content/docs/rag/`）
   - 対象ページのパスの一覧（しきい値より新しいページは対象外であることも書く）
   - 今日の日付（`lastUpdated` に書く値）
2. 完了の報告を待つ。報告にある「他の章との食い違い」は、最後にまとめて扱うためメモしておく
3. `npm run build` が通ることを確認する。失敗したら原因を直す
4. その章の変更をコミットする（例: `Refresh rag chapter content (2026-12)`）。サブエージェント自身にはコミットさせない
5. ユーザーに 1〜2 行で進捗を伝え（「RAG 章: 6 ページ見直し、3 ページ更新」など）、次の章へ進む

途中でセッションが止まっても、更新済みのページは `lastUpdated` が新しくなっているので、手順 1 からやり直せば残りの章だけが対象になる。

### 3. 仕上げ

1. **章をまたぐ食い違い:** サブエージェントの報告にあった食い違い（料金・モデル名・上限値など、同じ事実が複数の章に書かれているもの）を確認して直す
2. **トップページ（`src/content/docs/index.mdx`）:**
   - 「What's new」の表の先頭に、今回の更新を 1 行で追加する（主な更新ページへのリンクと内容）
   - 「前提とする 2026 年時点の状況」が古くなっていれば直す
   - `lastUpdated` が対象なら、トップページ自体も見直す
3. `npm run build` を確認してコミットし、ブランチを push して PR を作る。PR の本文には章ごとの更新内容、主な出典、確認しきれなかった点を書く
4. ユーザーに最終報告をする: 更新した章とページ数、主な変更点、要確認の点、PR の URL
