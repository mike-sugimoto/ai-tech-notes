## このサイトの目的

**AI Tech Notes** は、**若手エンジニアが LLM（大規模言語モデル）の基礎を学ぶ** ための技術ノートです。
トークンやコンテキストウィンドウといった土台から始めて、RAG・MCP・エージェント開発へと順に進みます。
題材には社内ナレッジ（Microsoft 系のデータ）を使った **AI 回答 / ドラフト作成 / レビュー支援** を取り上げ、
最後にそれらを組み合わせたシステム構成（アーキテクチャ）を発展編として扱います。

目指すのは、**「LLM がなぜそう振る舞うのか」を理解し、「何を選び、なぜそう作るか」を自分で説明できる状態** です。

## 読み進め方

サイドバーの上から順に読むと、基礎から発展へ無理なく進めるように並べています。

1. **[LLM の基礎](/ai-tech-notes/llm-basics/)** — トークン・コンテキストウィンドウ・モデル選定・生成の制御。以降のすべての章の土台
2. **[RAG](/ai-tech-notes/rag/) → [MCP](/ai-tech-notes/mcp/)** — LLM に社内の知識やツールを渡す 2 つの方法
3. **[エージェント開発](/ai-tech-notes/agents/)** — エージェントに仕事を任せるための考え方と仕組み
4. **[データソース](/ai-tech-notes/data-sources/) / [データ設計・形式](/ai-tech-notes/data-modeling/)** — AI に読ませるデータの集め方・整え方
5. **[コスト・ROI](/ai-tech-notes/cost-roi/)** — 料金の仕組みと、コストを抑える工夫
6. **[アンチパターン](/ai-tech-notes/anti-patterns/)** — ここまでの内容を「よくある失敗」から振り返る
7. **[ユースケース（発展）](/ai-tech-notes/use-cases/)** — 学んだ要素を組み合わせ、ユースケースごとのシステム構成を確認する

## スコープ

- **想定読者:** LLM を使った開発に関わり始めた若手エンジニア（プログラミングの基本は分かる前提）
- **扱う題材:** Microsoft 系を中心とした社内データ（File Server / Confluence / JIRA / GitHub / SharePoint）
- **扱う題材:** 汎用 LLM（Claude / GPT / Gemini など）を API・クラウド経由で利用する構成
- **対象外:** Google Workspace 系（Drive / Docs など）
- **対象外:** モデルの事前学習・ファインチューニングの実装詳細、オンプレミス GPU 基盤の構築

## 前提とする 2026 年時点の状況

このサイトの記述は、次のような現在の状況を前提にしています。

- **RAG は「作り込むもの」から「選ぶもの」へ。** ハイブリッド検索・リランク・権限トリミング・
  エージェント型検索がマネージドサービスで提供され始め、自前実装の範囲を選べるようになった。
- **MCP が AI とツール/データをつなぐ標準になった。** 主要な AI クライアント・開発ツール・M365 Copilot が対応し、
  「静的知識は RAG、最新状態や操作は MCP」という役割分担が定着しつつある。
- **長いコンテキストとプロンプトキャッシュが一般化した。** 「全部渡す」ことは技術的には可能になったが、
  コスト・精度・権限の観点から **検索で絞ってから渡す** 設計の重要性は変わらない。
- **セキュリティの論点が具体化した。** 間接プロンプトインジェクションや過剰な権限（Excessive Agency）など、
  LLM 特有のリスクが OWASP などで体系化され、設計段階での対策が求められている。
