## このサイトの目的

**AI Tech Notes** は、社内ナレッジを対象とした **AI 回答 / ドラフト生成 / レビュー支援** システムを
設計・構築するときに「知っておくべきこと」を、抜け漏れなく一箇所にまとめた技術ノートです。
LLM の基礎から RAG・MCP・エージェント開発・データソース接続（Microsoft 系中心）・データ形式・
アンチパターン・コスト/ROI までを横断的に扱い、**「何を選び、なぜそう作るか」を判断できる状態**になることを目指します。

## 読み進め方

1. まず [推奨アーキテクチャ](/ai-tech-notes/use-cases/reference-architectures/) の前半（全体像・設計判断）で、システム全体を俯瞰する
2. 不安があれば [LLM の基礎](/ai-tech-notes/llm-basics/)（トークン・コンテキストウィンドウ・モデル選定）で土台を固める
3. 各論（[RAG](/ai-tech-notes/rag/) / [MCP](/ai-tech-notes/mcp/) / [エージェント開発](/ai-tech-notes/agents/) / [データ](/ai-tech-notes/data-modeling/)）を深掘りする
4. [アンチパターン](/ai-tech-notes/anti-patterns/) と [コスト・ROI](/ai-tech-notes/cost-roi/) で実装判断を固める
5. 最後に [ユースケース](/ai-tech-notes/use-cases/) で自分のケースに近い構成を確認し、ここまでの知識を当てはめる

## スコープ

- **対象:** Microsoft 系を中心とした社内データ基盤（File Server / Confluence / JIRA / GitHub / SharePoint）
- **対象:** 汎用 LLM（Claude / GPT / Gemini など）を API・クラウド経由で利用する構成
- **対象外:** Google Workspace 系（Drive / Docs など）
- **対象外:** モデルの事前学習・ファインチューニングの実装詳細、オンプレミス GPU 基盤の構築

## 前提とする 2026 年時点の状況

このサイトの記述は、次のような現在の状況を前提にしています。

- **RAG は「作り込むもの」から「選ぶもの」へ。** ハイブリッド検索・リランク・権限トリミング・
  エージェント型検索がマネージドサービスで提供され始め、自前実装の範囲を選べるようになった。
- **MCP が AI とツール/データをつなぐ標準になった。** 主要な AI クライアント・開発ツール・M365 Copilot が対応し、
  「静的知識は RAG、最新状態や操作は MCP」という役割分担が定着しつつある。
- **長いコンテキストとプロンプトキャッシュが一般化した。** 「全部渡す」ことは技術的には可能になったが、
  コスト・精度・権限の観点から **検索で絞ってから渡す** 設計の重要性は変わらない。
- **セキュリティの論点が具体化した。** 間接プロンプトインジェクションや過剰な権限（Excessive Agency）など、
  LLM 特有のリスクが OWASP などで体系化され、設計段階での対策が求められている。
